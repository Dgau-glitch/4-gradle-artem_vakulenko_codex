# Задание 4. Gradle

Вам дан готовый исходный код небольшого приложения на Kotlin под JVM платформу.
Ваша задача - настроить все необходимые зависимости и сборку через Gradle.

Вам запрещено изменять исходный код проекта в директории `src/main` и файлы CI.
Вам разрешено изменять gradle-конфигурацию проекта, добавлять вспомогательные конфигурационные файлы, тесты в директорию `src/test`.

## 1. Язык и библиотеки
Прочитайте про использование [Version Catalogs](https://docs.gradle.org/current/userguide/version_catalogs.html) для указания зависимостей и версий библиотек в специальном файле.
Создайте `libs.versions.toml` файл в директории `gradle` и опишите в нем все плагины, библиотеки и зависимости, которые требуются для сборки проекта.

Язык программирования (нужно подключить как plugin):
* Kotlin JVM 2.2.20 ([link](https://kotlinlang.org/docs/gradle-configure-project.html#targeting-the-jvm)).

Библиотеки (libraries):
* Datetime 0.7.1 ([link](https://github.com/Kotlin/kotlinx-datetime));
* CliKt 5.0.3 ([link](https://ajalt.github.io/clikt/)).

Описание версий всех зависимостей должно быть в отдельной секуции файла.

Теперь воспользуйтесь описанными в `libs.version.toml` зависимостями из файла `build.gradle.kts`.
* Подключите `kotlin` плагин в блоке `plugins`.
* Укажите maven репозиторий, из которого будут скачиваться необходимые библиотеки (в нашем случае `mavenCentral`).
* Добавьте все необходимые `implementation` зависимости в блоке `dependencies` (все зависимости должны браться одним списком из libs файла).

Если вы все сделали правильно, запуск команды `./gradlew build` в корне репозитория завершится успешно.

## 2. Сборка и документация
Подключите плагин `shadowJar` ([link](https://gradleup.com/shadow/)) для сборки кода проекта вместе с необходимыми зависимостями в jar-файл.
Для этого добавьте определение и версию плагина в соответствующие секции `libs.version.toml` и подключите его через `alias` в секции `plugins` файла `build.gradle.kts`.

Если вы все сделали правильно, запуск команды `./gradlew shadowJar` соберет jar-файл, который будет находиться в директории `build/libs/gradle-dateutil-1.0.0-all.jar`.
Попробуйте запустить собранное приложение через `java -jar build/libs/gradle-dateutil-1.0.0-all.jar`.

Аналогичным образом подключите плагин `dokka` для генерации документации по комментариям в исходном коде.
Команда `./gradlew dokkaHtml` сгенерирует документацию в формате html в директории `build/dokka/html/index.html`.
Проверьте, что это действительно так.

Добавьте в `build.gradle.kts` задачу с названием `release`, которая будет собирать jar-файл и генерировать документацию,
используя другие gradle tasks (через shadowJar и dokkaHtml).
Таким образом, вызов `./gradlew release` будет одновременно собирать все необходимые артифакты нашего проекта. 

## 3. Тестирование:
Подключите следующие библиотеки для написания тестов
* Mockk 1.14.6 ([link](https://mockk.io));
* Kotest 6.0.4 ([link](https://kotest.io)).

Добавьте библиотеки как `testImplementation` зависимости в блоке `dependencies` (библиотеки также должны добавляться одним списком, определенным в libs файле).

Изучите возможности Kotest и Mockk, пользуясь документацией.
Добавьте тест (или несколько тестов) для демонстрации работы подключенных библиотек.
Вы не обязаны покрывать тестами всю функциональность приложения, достаточно показать, что библиотеки работают. 

Для демонстрации работы библиотеки Mockk, в текстах замените результат какой-нибудь функции в проекте на фиксированное тестовое значение, __не меняя исходный код приложения__.
Вероятно, будет удобно заменить результат `Clock.System.now()` на фиксированное значение,
чтобы запуск программы с аргументами `diff 2024-09-01T12:00:00` (в таком случае считается разница между заданной датой и текущим моментом времени) всегда возвращал фиксированный результат.

## 4. Проверка форматирования и статический анализ

Подключите инструменты для проверки качества кода, используя:
* KtLint 1.7.1 ([link](https://pinterest.github.io/ktlint/1.7.1/)) через gradle плагин 13.1.0 ([link](https://github.com/JLLeitschuh/ktlint-gradle));
* Detekt 1.23.7 ([link](https://detekt.dev)).

Настройте KtLint и Detekt так, чтобы они разрешали использовать импорты со `*` вида:

```kotlin
import java.util.*
```

Требуется, что бы файлы настройки линтера и форматера лежали в корне проекта.

## Отправка на проверку
Итоговое решение должно собираться через команду `./gradlew build`.
Команда `./gradlew release` должна генерировать jar-файл проекта и Dokka HTML документацию в директориях `build/libs` и `build/dokka` соответственно.

Готовое решение добавьте в ветку `solution`.
После отправки решения убедитесь, что тесты прошли (загорелась зеленая галочка в CI).
